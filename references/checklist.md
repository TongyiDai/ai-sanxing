# 三省检查清单（可操作版）

写自省清单时对照用。不必逐条抄进输出，挑与本次交付物相关的用。每条问题都要么给出证据判"过"，要么标出问题+严重度。

---

## 一省 · 是否可信

**核心问题：有没有编的？有没有不该信却被当真的？**

- [ ] **来源可溯**：文中每个具体事实、数字、名称、日期、引用、链接、断言，我能说出它从哪来吗？说不出的一律标为嫌疑项。
- [ ] **未越界**：有没有输出用户没给、我也没查证的信息？（用户给 A/B/C，我写了 D → D 存疑）
- [ ] **数字与计算**：涉及金额、比例、汇总、增长率的地方，重算一遍对得上吗？单位、口径一致吗？
- [ ] **引用忠实**：引号里的话、转述的观点，和原文一致吗？有没有断章取义或夸大？
- [ ] **因果不硬凑**：结论链条里每一步都站得住吗？有没有"听起来顺但没验证"的一环？
- [ ] **语气 ≠ 事实**：有没有用肯定语气掩盖了本该存疑的地方？"显然/必然/一定"后面的东西查过吗？
- [ ] **链接/路径有效**：给出的链接、文件路径、引用位置，真的存在且指向对的东西吗？（可回读验证的就回读）

判定话术：能核实的 → 核实后写"已核对，一致"；核实不了的 → 写"未能核实，标注为不确定"，**不要**假装确定。

---

## 二省 · 是否完整

**核心问题：用户要的每一件，我是不是都做了？**

- [ ] **子诉求拆解**：把原始请求拆成一条条可判真假的子任务，逐条对照产出，标"已覆盖 / 部分 / 漏"。
- [ ] **多部分请求**：形如"做 A 并顺便 B""先 X 再 Y"的，有没有只做了一半？
- [ ] **隐含约束**：格式、篇幅、语言、口吻、结构、字段完整性，用户明说或默认期待的，满足了吗？
- [ ] **边界与异常**：空数据、缺字段、超长、失败情况，处理了还是装作不存在？（业务表缺数据优先用明确占位如"无"而非留白）
- [ ] **内部自洽**：目录/标题/编号/交叉引用对得上吗？前面承诺的"下面给出/见后文/附表"真的兑现了吗？
- [ ] **无残留占位**：有没有 TODO、待补、"此处略"、半截的句子或没填的模板？

判定话术：写"子诉求覆盖 x/y；漏了：……"，把没覆盖的直接列出来。

---

## 三省 · 是否合意

**核心问题：我答的，是不是用户真正想要的那个？**

- [ ] **真问题 vs 字面**：用户字面要的，和他真正想解决的，是一回事吗？我有没有在精准回答一个错的问题？
- [ ] **形态对**：他要结论还是过程？草稿还是终稿？清单还是长文？摘要还是全文？给多了/给少了？
- [ ] **深度对**：深浅是否匹配场景——该给判断的地方给了判断，还是只堆了信息让他自己捞？
- [ ] **口吻对**：正式/随意、给谁看、中英文，符合场景吗？
- [ ] **偏好与约束**：有没有违反已知偏好（如中文要克制、别 AI 味、终稿别留过程话术、账号/租户边界、隐私红线）？
- [ ] **第一反应测试**：现在直接发出去，用户最可能说"对，就是这个"还是"你没懂我"？后者就得改。

判定话术：指出具体的意图偏差点，或写"形态/深度/口吻均对齐，理由是……"。

---

## 严重度分级（用于排修改优先级）

- **高**：错误信息、编造、漏掉核心诉求、答错了问题——不修就是硬伤，必须处理。
- **中**：部分覆盖、口吻/形态偏差、次要事实存疑——影响体验或可信，尽量修。
- **低**：措辞、排版、可改可不改的小瑕疵——时间允许再修。

## 到顶时怎么交底（3 轮上限后）

不要假装完美。用这个句式如实报告：
> 已自省 3 轮，仍有以下未能消除：①<问题>（原因：<为何没修掉>）。建议：<给用户的选项，如"要不要我换个来源再查/要不要放宽这条要求">。
